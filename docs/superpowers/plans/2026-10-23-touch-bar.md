# Touch Bar implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Execution stays in this session.

**Goal:** Add the six approved native Touch Bar action buttons.

**Architecture:** A macOS-only module owns native buttons and their callback targets per window. Window rendering supplies availability and session context. Taps use existing app behavior and retain keyboard focus.

**Tech stack:** Rust, GPUI, objc2, AppKit.

**Spec:** `docs/superpowers/specs/2026-10-23-touch-bar-design.md`

## Global constraints

- Preserve the existing Touch Bar-related window lifecycle workaround.
- Compile the native integration only on macOS.
- Preserve unrelated working-tree changes.
- No settings, automatic message submission, approval buttons, or custom drawing.

## Review focus

- Detached windows must target their own focused session.
- Stop must disable when generation finishes or focus changes to an idle session.
- Callback targets must outlive their buttons without retaining the app permanently.
- Hidden and reused windows must receive current context.
- A machine without a Touch Bar must still run normally.

## Verification record

- macOS `cargo check --locked -p aether`: passed.
- `cargo test --locked --workspace`: passed, 1,417 tests and 8 ignored.
- Focused tests cover Stop state and routing, empty retained windows, focus
  changes, detached Files and Commands while main shows Settings, and detached
  New Chat opening in the main workspace.
- The detached Files regression first failed by switching the main window to
  Chat. Temporarily establishing Chat context for detached actions and restoring
  main navigation made the test pass.
- A temporary standalone GPUI example used the production native module. It
  verified six native template items, enabled-state updates, native bar reuse,
  and AppKit `performClick:` reaching the GPUI event receiver. It captured the
  hardware Touch Bar with all six buttons and the system Control Strip visible.
  The temporary example was removed afterward. Physical finger taps and operation
  on a machine without Touch Bar hardware were not exercised.
- A separate read-only code review found no blocking findings. Its one minor
  request was to document and test detached New Chat behavior; both are done.
- Changed Rust files pass formatting and `git diff --check`. Full workspace
  formatting still reports differences in unrelated existing files; these were
  left untouched.
- Existing `block v0.1.6` future-compatibility warning remains.

## Follow-up

Native icons were added to the action labels. The user subsequently requested
removing Stop to prevent accidental cancellation. Stop was removed from the
native items and action routing; the bar now has five controls. Earlier six-button
and Stop verification entries above describe the original implementation.
