# Windows support: terminal, git/worktrees, filesystem, config, notes, notifications, tests

Scope: `crates/terminal`, `crates/git`, `crates/explorer`, `crates/core/src/paths.rs`, `crates/app` (notes, notify, settings, open_in), and every `cfg(unix)` / `cfg(target_os)` test. Read-only survey, nothing edited. Effort: S under half a day, M one to three days, L a week or more.

Line numbers are against the tree at `feat/misc` (01d6250). Facts about `alacritty_terminal` were read from the 0.26.0 source in the local cargo registry (`src/tty/windows/`), not from memory.

## 0. Findings that block everything else

These make Windows fail in the first minute, regardless of feature. Fix them first.

1. **`aether-core::paths` assumes `:`-separated PATH, no `.exe`, and `HOME`.** `find_binary` (`crates/core/src/paths.rs:61`) joins a bare name (`git`, `nvim`, `claude`) onto each dir and tests `is_file()`, so on Windows it never finds `git.exe`. `search_dirs` splits on `:` (`paths.rs:83`), which cuts `C:\Windows;...` into garbage. `repaired_path` also splits and joins on `:` (`paths.rs:149,157`) and is the PATH handed to every terminal (`terminal/src/session.rs:160`). `run_login_shell` spawns `sh -l` (`paths.rs:108`), which falls back to plain `PATH` when `sh` is missing, so that part degrades safely.
2. **`home_dir()` reads only `HOME`** (`paths.rs:77`). Windows sets `USERPROFILE`, not `HOME` (only Git Bash/MSYS sets it). The result is an empty `PathBuf`, so `home_dir().join(".local/bin")` becomes a path relative to the cwd. Every caller (agent session discovery in `agent/src/external.rs:86-93`, `usage.rs:510,561,647`, `~/` expansion in `paths.rs:69`, `app/src/terminal.rs:50`, sidebar project key `app/src/app/sidebar.rs:43`) silently looks in the wrong place. Fix: `std::env::home_dir().unwrap_or_default()` (std resolves `USERPROFILE` / known folder). `config_dir` already calls `env::home_dir()` on macOS; only the free function is wrong.
3. **`std::fs::canonicalize` returns `\\?\C:\...` verbatim paths on Windows.** Used in `git/src/worktree.rs:152,182,397,420,435,473,563,594,595,684`, `app/src/notes/external.rs:15-16`, `app/src/notes/store.rs:60`. Those paths then go to (a) `git worktree add -- <path>` (`worktree.rs:190-193`), (b) the PTY working directory (`cmd.exe` refuses `\\?\` and `\\server\` cwds and falls back to `C:\Windows`), (c) `nvim`, (d) `starts_with` against user-typed `C:\...` paths, which never match a `\\?\` root (`store.rs:111-113` would reject every absolute note path not built from the canonical root). `dunce` is already in `Cargo.lock`; or write a 6-line `simplify()` that strips `\\?\` when the rest is a plain drive path. Put it in `aether-core` and replace every `.canonicalize()` call.
4. **`mod browser;` is unconditional (`app/src/main.rs:7`) but `wry` is only a dependency on macOS and Linux (`app/Cargo.toml` target table).** The app crate will not compile on Windows until the browser module is gated or `wry` (WebView2) is added for `cfg(windows)`. Other researchers likely own this; listed because it gates the test run.
5. **`agent/src/orchestrator/server.rs:3-4` and `orchestrator/mod.rs:5` import `std::os::unix::{fs::PermissionsExt, net::UnixListener/UnixStream}` with no cfg.** Hard compile error on Windows. Out of my crates, but it blocks `cargo test --workspace`. Replace the transport with a named pipe or loopback TCP with a token file; see the notes/nvim section for the same decision.
6. **GUI subsystem and console windows.** No `windows_subsystem = "windows"` in `app/src/main.rs`, and no `CREATE_NO_WINDOW` on any `Command` (20 files spawn processes). In a GUI-subsystem exe every `git`, `nvim`, `where` spawn flashes a console window; in a console-subsystem exe the app drags a terminal window along. Fix: `#![cfg_attr(windows, windows_subsystem = "windows")]` plus one `aether_core::quiet(&mut Command)` helper calling `CommandExt::creation_flags(0x0800_0000)`, applied in `git::run_with`, `hunk::run_stdin`, `notes/external::run_with_timeout`, `open_in::run_with_deadline`, `explorer::ops::trash`, `agent`, `driver`.

## 1. Terminal (`crates/terminal`, `crates/app/src/terminal.rs`)

### 1.1 What alacritty_terminal 0.26 does on Windows

- Backend is ConPTY only (`tty/windows/conpty.rs`). It looks for a `conpty.dll` next to the exe first (`ConptyApi::new`, `conpty.rs:52-90`) and falls back to `kernel32` `CreatePseudoConsole`. Needs Windows 10 1809+. Shipping `conpty.dll` + `OpenConsole.exe` from the Windows Terminal release gives newer VT behavior than the in-box console host. Optional, S.
- Default shell when `Options.shell` is `None` is the literal `powershell` (`windows/mod.rs:159`). Aether always sets `shell`, so that default is never used.
- `cmdline()` (`windows/mod.rs:158-176`) pushes `shell.program` **unquoted** and appends args; args are quoted only when `Options.escape_args` is true. `Options::default()` on Windows sets `escape_args: false` (`windows/mod.rs:232`). `session.rs:154-162` already notes the extra field and uses `..Options::default()`. Aether must set `escape_args = true` under `cfg(windows)` and quote the program path itself (`C:\Program Files\PowerShell\7\pwsh.exe` contains a space).
- `working_directory` and `env` are honored (`conpty.rs:206-211`). `convert_custom_env` (`conpty.rs:246-292`) merges the custom map over the inherited environment case-insensitively (custom wins). So `PATH` set by Aether replaces `Path` correctly. Variables cannot be removed, same as Unix.
- Resize goes through `ResizePseudoConsole` via `on_resize` (`windows/mod.rs:123`). `Session::resize` (`session.rs:209`) is portable as is. Known ConPTY behavior: it reflows and repaints, so the prompt line may flicker on resize; not fixable in Aether.
- There is no `Pty::child()`, no pid, no fd. `session.rs:164-170` already sets `pid = 0, master = -1` for `not(unix)`.

## 3. Config and data directories (`crates/core/src/paths.rs`)

## 8. Recommended order

1. **Core primitives (S, one PR, unblocks all).** `home_dir()` via `env::home_dir()`; `find_binary` + `executable` with `PATHEXT` and `env::split_paths`; `repaired_path` returns plain PATH on Windows; `simplify()` replacing every `canonicalize()`; `quiet(Command)` helper; `config_dir`/`cache_dir`/`data_dir` for `%APPDATA%`/`%LOCALAPPDATA%`; `windows_subsystem`.
2. **Make it compile (S/M).** Gate `mod browser` or add the WebView2 `wry` target; replace unix-socket orchestrator transport; gate or port the ungated Unix test helpers in section 7B. Add the `windows-latest` CI job running `cargo check` first, then tests.
3. **Git (S, mostly mechanical).** `git.exe` discovery and message, `core.longpaths`, `GCM_INTERACTIVE=never`, `taskkill`-based `stop`, hash normalisation in `repo_dir`, tests for `safe_path` and junctions. After this the Git panel and worktrees work.
4. **Terminal MVP (M).** `user_shell` with pwsh/powershell/cmd, per-shell args, `escape_args`, program quoting, skip `/usr/bin/env` rewrite, `terminate` via `Msg::Shutdown`, flip the five `cfg!(unix)` UI gates (not `resume_command_of`), AltGr fix in `keys.rs`. Defer `running_job`.
5. **Explorer and reveal (S).** `trash` crate on Windows, case-only rename, "Show in Explorer" label helper, verify `reveal_path`/`open_url` in gpui.
6. **Notes (M).** Named-pipe default, PowerShell `quote`, hide tmux settings, `hard_link` fallback, symlink/junction tests.
7. **Retry and robustness (S/M).** Rename retry in `settings::save`, worktree-removal retry plus closing PTYs in the folder, `autocrlf` handling for hunk revert.
8. **Notifications, voice copy, sysinfo, open-in apps, taskbar badge, `running_job` (M/L).** Polish after the app is usable.

Open questions that need a Windows machine (not verifiable from this repo): how gpui-pre reports `key_char` for AltGr; whether `show_system_notification` and `reveal_path` have Windows implementations; whether `git worktree add` accepts a `\\?\` path in the Git for Windows version CI installs (the `simplify()` fix makes the question moot); whether `git apply --reverse` fails on CRLF work trees with `autocrlf=true` as predicted.
